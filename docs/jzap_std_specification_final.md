# `jzap-std` 라이브러리 최종 기획서

문서 버전: 1.1 · 기준일: 2026-11-03 (한국 표준시)

독립 라이브러리의 개발 범위, 실패 계약, 구현 순서와 검증 기준을 정의한다. 8개 모듈군은 전체 개발 범위이며, 첫 구현 단위는 공통 계약과 기본 소유 타입이다. 확장 컬렉션, 공유 소유권과 시스템 런타임은 각 단계의 완료 기준을 충족한 뒤 지원 범위에 편입한다. 기존 코드의 검증 결과는 차용 근거이며 새 라이브러리의 완료 판정은 7절을 따른다.

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 라이브러리 명칭 | `jzap-std` |
| 명칭 약어 | **J**ustified **Z**ero-**A**bort **P**anic-free **Std** |
| 패키지와 사용 경로 | Cargo 패키지명 `jzap-std`, 라이브러리 crate명 `jzap`, 사용 경로 `jzap::…` |
| 분류 | 고신뢰 시스템을 위한 Rust 표준 라이브러리 일부의 실패 가능한 대체 API 및 검증 체계 |
| 적용 대상 | 스토리지 엔진, 데이터베이스 코어, GPU·WebAssembly 렌더러, 실시간 계측 데몬, 로보틱스 및 무인 시스템 |
| 핵심 목표 | 라이브러리가 통제하는 명세된 실패를 명시적으로 반환하고, 자원 한도와 실패 후 상태를 일관되게 관리 |
| 개발 방식 | 공통 단위 연산의 계약·구현·검증·성능 평가를 먼저 완료한 뒤 소비 라이브러리에 이식 |

Cargo의 기본 이름 변환에 의존하지 않고 다음과 같이 라이브러리 이름을 지정한다.

```toml
[package]
name = "jzap-std"

[lib]
name = "jzap"
```

프로젝트 명칭은 개발 목표를 나타낸다. 배포 버전의 실제 보장 범위는 지원 API, 대상 플랫폼, 기능 조합, 의존성 및 검증 기록으로 식별한다.

## 2. 배경, 목표 및 보장 범위

### 2.1 배경

Rust 표준 라이브러리는 편의성과 성능을 제공하는 한편, 일부 API에서 할당 실패 시 프로세스를 종료하거나 잘못된 인덱스·용량·연산 입력에 대해 패닉을 발생시킨다. 이미 오류를 반환하는 API도 있지만, 반환형이 `Result`라는 사실만으로 내부의 모든 할당과 호출 경로가 실패를 반환한다고 볼 수는 없다.

여러 제품에서 이러한 동작을 개별적으로 보완하면 구현, 실패 계약, 검증 하네스가 중복된다. `jzap-std`는 공통 구현과 검증을 독립 라이브러리에 모아 일관된 API로 제공한다.

### 2.2 핵심 목표

1. 지원 API에서 명세된 오류를 처리하기 위해 `panic!`, `abort`, 실패 불가능한 재할당 등의 경로를 사용하지 않는다.
2. 암묵적 할당이나 인덱스 패닉을 노출하는 소유 타입의 메서드·트레이트를 제거하고, 실패 가능한 대체 연산을 제공한다.
3. 메모리 예산, 요소 수 상한, 사전 확보 용량을 구분하여 통제한다.
4. 실패 시 입력 소유권, 기존 데이터, 부분 진행량과 예산의 상태를 명시한다.
5. 단위 API를 먼저 검증하고, 이후 타입과 오류 전파 경로를 모듈 단위로 이식한다.
6. 자동 제거, 재시도, 지연, 화면 경고, 재시작 등 복구 정책은 소비 애플리케이션이 선택한다.

### 2.3 보장 계약

> 지원하는 대상·기능·의존성 구성에서, 명세된 오류 조건 때문에 라이브러리가 직접 panic 또는 abort하지 않는다. 실패는 명시적으로 반환하며, 연산별 상태·소유권·예산 보존 계약을 만족한다. 호출하는 사용자 코드와 외부 실행 환경에 필요한 전제조건을 함께 명시한다.

다음 책임 경계를 사용한다.

| 범위 | 계약 |
| --- | --- |
| 라이브러리 자체 구현 | 내부 할당, 범위·산술 검사, 오류 생성, 정리 및 예산 관리를 검증한다. 범위 오류, 크기·산술 오버플로우, 용량·예산 초과, 할당자 거부, 참조 카운트 포화와 지원 콜백의 반환 오류는 처리 대상이며 전제조건으로 제외하지 않는다. 이러한 실패 때문에 내부 panic 또는 abort에 도달하면 라이브러리 결함이다. |
| 포함한 외부 구현 | 선택된 의존성의 실제 실행 경로도 검토·검증 대상이다. 외부 crate라는 이유로 내부 할당을 보장 범위에서 자동 제외하지 않는다. |
| 사용자 제공 코드 | `Hash`, `Eq`, `Ord`, `Display`, `Drop`, `TryClone`, 초기화 함수, 반복자와 클로저의 행동을 전제조건으로 명시한다. 트레이트 이름만으로 무패닉·무할당을 증명하지 않는다. |
| 호출자 코드 | 반환된 `Result`의 `unwrap`, 원시 슬라이스 인덱싱, 별도 표준 할당 등은 정책 검사와 통합 검증으로 관리한다. |
| 실행 환경 | 할당자가 실패를 반환하지 않고 직접 종료하는 경우, 운영체제의 강제 종료, 스택 고갈, 외부의 정의되지 않은 동작 등은 이 라이브러리 API만으로 복구할 수 없다. |

사용자 콜백의 오류 반환과 패닉은 구분한다. `catch_unwind`를 할당 실패 처리의 대체 수단으로 사용하지 않으며, `panic=abort` 구성에서도 명세된 오류 경로는 정상적으로 반환되어야 한다.

실패 가능성이 없는 조회와 빈 객체 생성에는 불필요한 `Result`를 강제하지 않는다. 값의 부재는 `Option`, 연산 실패는 `Result` 등 의미에 맞는 반환형을 사용한다.

## 3. 구현 대상: 8개 모듈군

아래 모듈군을 전체 개발 범위로 유지한다. 공개 API별 지원 상태는 구현 예정, 검증 중, 지원으로 구분하며, 미구현 기능을 검증된 대체 기능처럼 노출하지 않는다.

### 3.1 공통 오류 및 리소스 예산 (`jzap::error`, `jzap::budget`)

| 항목 | 요구사항 |
| --- | --- |
| `AllocError` | 할당자 거부와 할당 레이아웃 크기 초과를 구분한다. 재시도로 해결되지 않는 크기 오류를 메모리 부족과 혼동하지 않는다. |
| `BudgetError` | 논리적 메모리 예산의 예약 실패를 나타낸다. 할당자 실패와 별도로 식별한다. |
| `CapacityError` | 컨테이너에 설정한 요소 수·바이트 길이·사전 확보 용량 상한 초과를 나타낸다. |
| `BoundsError` | 인덱스·범위 오류, 길이 불일치 및 UTF-8 문자 경계 위반을 구분한다. |
| `ArithmeticError` | 오버플로우, 언더플로우, 0 나누기, 잘못된 시프트 폭, 무손실 연산에서의 정보 손실을 표현한다. |
| `RefCountError` | 참조 카운트 증가의 상한 도달을 나타낸다. 객체가 이미 해제되어 Weak 승격이 불가능한 상태와 구분한다. |
| `RuntimeError` | 운영체제 자원 오류, 동기화 상태, 시간 연산, 입출력 실패를 고정 크기 정보로 표현한다. |
| `TryClone` | 값 또는 핸들의 복제 실패를 반환한다. 임의의 표준 `Clone`을 호출하는 포괄 구현(blanket implementation)을 제공하지 않는다. |
| 대상 예산을 지정하는 복제 | `try_clone_in` 계열로 새 소유 메모리를 어느 예산에 청구할지 지정한다. 중첩 필드의 복제에도 해당 정책을 전파한다. |
| `TryInit` | 확보된 저장소의 실패 가능한 초기화와 부분 초기화 정리를 규정한다. |
| `MemoryBudget` | 모듈·작업 단위 메모리 한도, 예약량과 점유량을 관리한다. 구체적인 계측 계약은 5절을 따른다. |

오류 생성과 반환에는 새 힙 할당이 없어야 한다. 동적 오류 문자열, 자동 backtrace 수집, 오류를 담기 위한 `Box`를 필수 경로로 사용하지 않는다. 진단은 오류 종류, 수치, 정적 메시지와 운영체제 오류 코드 등으로 구성한다. 오류를 나중에 문자열로 만드는 작업도 실패 가능한 별도 연산으로 취급한다.

`TryClone`의 기본 복제는 원본의 명시된 예산 정책을 따른다. 다른 예산으로 복제하려면 대상 예산을 지정한다. 공유 핸들 복제는 공유 할당의 소유 예산을 변경하지 않는다. 예산 인자의 수명, 소유 방식 및 오류 타입의 구체적인 Rust 서명은 기초 단계에서 확정한다.

`try_clone_in`의 대상 예산은 이번 연산에서 새로 소유하게 되는 할당에 적용한다. `Vec<Arc<T>>`를 복제하면 새 벡터 저장소는 대상 예산에 청구하지만 공유된 `T`의 기존 할당은 원래 예산에 남는다. 공유 payload까지 새 예산으로 분리 복사하는 동작은 별도의 명시적 API로 제공하며, 핸들 복제의 의미를 조용히 깊은 복사로 바꾸지 않는다.

### 3.2 스마트 포인터 및 소유권 (`jzap::boxed`, `jzap::sync`, `jzap::rc`)

| 타입 | 요구사항 |
| --- | --- |
| `Box<T>` | 실패 가능한 단일 할당과 입력 소유권 반환을 제공한다. 암묵적 할당을 수행하는 `From`·`Clone`을 구현하지 않는다. |
| `Box<[T]>` | 길이·레이아웃 검사, 할당, 원소 초기화, 중간 실패 시 초기화된 원소만 정리하는 경로를 제공한다. |
| 제자리 초기화 | 큰 `T`를 먼저 스택에 완성해야 하는 `try_new(value)`와 구분하여 제공한다. 초기화 완료 전에는 완성된 `T`의 참조나 소유권을 노출하지 않는다. |
| `Arc<T>` / `Weak<T>` | 최초 할당, 핸들 증가 및 승격 등에서 발생하는 명세된 실패를 반환한다. 강한 참조(strong)·약한 참조(weak)의 카운트와 할당 수명을 함께 검증한다. |
| `Rc<T>` / `Weak<T>` | 단일 스레드에서 동일한 소유권·카운트 상한 계약을 제공한다. |

Arc의 카운트 확인과 증가는 하나의 원자적 상태 전이로 구현한다. 현재 카운트를 읽은 다음 표준 `Arc::clone`을 호출하는 방식은 허용하지 않는다.

복제, downgrade, upgrade, 마지막 strong 해제, 마지막 weak 해제, 가변 접근 및 복사 후 수정 기능을 하나의 소유권 프로토콜로 설계한다. 강한 참조가 모두 해제된 객체를 가리키는 Weak의 승격은 값의 부재로, 살아 있는 객체의 카운트 포화는 오류로 구분할 수 있는 반환형을 사용한다.

공유 할당은 한 번만 계측한다. 값이 소멸해도 Weak 때문에 제어 블록과 할당 영역이 유지된다면 해당 실제 요청 영역의 예산도 유지한다. 표준 `Clone`은 참조 카운트 상한 오류를 표현하지 못하므로 이 포인터 타입에 제공하지 않는다.

### 3.3 선형 컬렉션 및 슬라이스 (`jzap::vec`, `jzap::deque`, `jzap::slice`)

| 타입·규격 | 요구사항 |
| --- | --- |
| `Vec<T>` | 생성, 예약, 추가, 확장, 삽입, 크기 변경, append, 복제를 실패 가능한 연산으로 제공한다. 인덱스 연산자와 암묵적 성장 트레이트를 제공하지 않는다. |
| `BoundedVec<T>` | Vec의 생성 시 상한 지정 기능과 같은 제한 계약을 사용한다. 지정된 최대 요소 수를 모든 생성·확장·변환 경로에서 지킨다. 메모리 예산과 요소 수 상한은 독립적으로 적용한다. |
| `ScratchBuf<T>` | 직접 소유하되 최초 확보한 저장소 안에서만 사용한다. 실행 중 재할당을 금지한다. 원소나 콜백의 별도 할당은 추가 계약으로 관리한다. |
| 외부 저장소를 빌리는 scratch 뷰 | 호출자가 제공한 저장소를 빌려 사용하고 생성 시에도 할당하지 않는다. 초기화된 원소 수, 정렬과 수명 및 원소 정리 책임을 추적한다. |
| `VecDeque<T>` | 전후방 삽입, 성장, 회전·연속화, 복사·복제의 할당과 이동을 검토한다. 성장 실패 시 원소 순서와 소유권을 보존한다. |
| 안전 슬라이스 인터페이스 | 접근, 범위 조회, 분할, 길이 일치 복사, 교환을 검사된 메서드로 제공한다. |
| 실패 가능한 반복자 수집 | `collect`, `extend`, `to_vec` 등에 대응하는 명시적 API를 제공하고, 반복자 오류와 할당 실패 시 입력 소비·부분 결과 계약을 명시한다. |

사용자 추가 요구(2026-11-03): `Vec` 자체를 생성할 때 선택적으로 최대 원소 수를 지정할 수 있어야 한다. 이 상한은 현재 확보 용량(`capacity`)이나 바이트 예산과 별개다. 상한과 같은 길이는 허용하며, 초과하려는 연산은 명시적 오류를 반환한다. 삭제·비우기 후에는 같은 상한 안에서 다시 추가할 수 있다. 상한 지정만으로 최대 크기를 미리 할당하지 않으며, 기하급수적 성장의 여유분도 지정 상한을 넘겨 요청하지 않는다. 예약·추가·삽입·확장·크기 변경·변환 등 모든 증가 경로에 적용하고, 크기 0 타입도 원소 수로 검사한다. 단건 거부 시 기존 내용과 입력 소유권을 보존하며, 다건 연산의 오류 후 상태와 반복자 소비 계약은 연산별로 명시한다. 상한을 지정하지 않은 Vec에는 임의의 작은 기본 제한을 추가하지 않는다.

`Copy` 데이터의 다건 복사는 한 번의 필요한 예약 후 연속 복사를 사용한다. 임의 `Clone`을 원소별로 호출하여 실패를 숨기지 않는다. 깊은 복사가 필요한 원소는 `TryClone`을 사용한다.

소유 컨테이너를 감춘 래퍼에서 다시 표준 소유 컨테이너의 가변 참조를 노출하지 않는다. `&[T]` 같은 원시 뷰와 표준 반복자 트레이트를 노출하는 경우, 호출자가 표준 인덱싱·수집을 다시 사용할 수 있음을 API의 상호운용 경계로 표시한다. 엄격한 사용 환경에는 검사된 뷰와 정책 검사를 함께 제공한다.

### 3.4 문자열 및 포맷팅 (`jzap::string`, `jzap::fmt`)

| 타입·규격 | 요구사항 |
| --- | --- |
| `String` | 생성, 문자·문자열 추가, 삽입, 교체, 잘라내기, 바이트 변환, 부분 문자열 조회와 복제에서 할당·범위·UTF-8 조건을 검사한다. |
| `BoundedString` | 최대 바이트 길이를 모든 편집·포맷팅 경로에 적용한다. 바이트 길이와 문자 수를 혼동하지 않는다. |
| `try_format` / `try_write_fmt` | 대상 버퍼의 예산·용량·할당 실패와 포맷터 오류를 반환한다. 일반 `format!`으로 임시 문자열을 먼저 만드는 구현은 사용하지 않는다. |
| 문자열 변환 | `ToString`, `ToOwned` 등의 암묵적 할당에 대응하는 명시적 실패 가능 API를 제공한다. |

문자열 변경은 UTF-8 불변식을 유지한다. 무검사 가변 바이트 노출로 이를 우회하지 못하게 한다.

문자열 포맷팅은 반환된 오류에 대해 기존 내용 복원을 기본 계약으로 한다. 성공한 선행 예약으로 용량이 증가한 경우에는 이를 문서화한다. 쓰기 대상이 할당 실패를 기록한 뒤 사용자 포맷터가 그 오류를 무시하고 성공을 반환해도 최종 API는 실패를 반환해야 한다.

사용자 `Display`가 수행하는 별도 할당·패닉과 버퍼 자체의 실패 처리는 구분한다. 표준 출력이나 파일에 이미 기록한 바이트는 문자열 버퍼처럼 되돌릴 수 없으므로 3.7절의 부분 진행 계약을 따른다.

### 3.5 연관 컨테이너 및 우선순위 큐 (`jzap::collections`)

| 타입 | 요구사항 |
| --- | --- |
| `HashMap<K, V>` / `HashSet<T>` | 삽입, 예약, 재해시, 복제와 Entry 경로에서 실패를 반환한다. `Index`와 암묵적 할당 인터페이스를 제공하지 않는다. |
| 해시 시드 생성 | 난수 공급 실패를 반환하거나 호출자가 명시한 해셔를 받는다. 시드 생성 실패를 고정 시드로 조용히 대체하지 않는다. |
| `SortedMap<K, V>` / `SortedSet<T>` | 정렬 순서, 키 동등성, 탐색·삽입·삭제·범위 조회의 복잡도와 메모리 계약을 정의한다. 노드·배열 성장, 병합, 복제 실패를 반환한다. |
| `BinaryHeap<T>` | 추가, 병합, 복제, 용량 확장의 실패를 반환한다. 비교 연산의 전제조건과 실패 후 힙 불변식을 명시한다. |

해시맵은 원본 삽입 알고리즘 내부의 성장 지점을 실패 가능한 경로로 바꾼다. 외부에서 존재 확인·해시 계산을 반복한 뒤 기존 삽입을 호출하는 방식으로 정상 경로 비용을 늘리지 않는다. 알고리즘 자체가 요구하는 용량 분기와 탐색은 유지한다.

동등 키 갱신, 기존 키 객체 유지 여부, 반환되는 이전 값, 가득 찬 테이블에서의 갱신 실패 가능성을 계약에 포함한다. 예약 후 탐색하는 원본을 차용할 때, 기존 키 갱신도 예약 실패를 반환할 수 있다는 의미를 보존하거나 변경 이유를 명시한다. Entry의 occupied 경로는 불필요한 할당이나 값 생성 콜백을 실행하지 않는다.

`SortedMap`을 정렬 Vec로 구현할지 B-tree 계열로 구현할지는 해당 단계의 선행 설계 결정이다. 이 결정 전에는 표준 BTreeMap과 같은 성능 특성을 주장하지 않는다. 범위 조회는 결과 부재, 잘못된 범위, 결과를 소유 형태로 수집하는 추가 할당을 구분한다.

### 3.6 안전 산술 및 수치 변환 (`jzap::num`, `jzap::convert`)

| 항목 | 요구사항 |
| --- | --- |
| `Checked<T>` | 정수 덧셈·뺄셈·곱셈·나눗셈·나머지·절댓값·부호 반전·시프트에 검사된 메서드를 제공한다. 디버그와 릴리스의 오류 의미를 일치시킨다. |
| 무손실 정수 변환 | 폭 축소, 부호 변경과 대상 범위를 검사한다. 이미 무손실인 변환은 `From` 같은 실패 불가능한 연산을 사용할 수 있다. |
| 정수→실수 변환 | 범위뿐 아니라 정밀도 손실도 정의·검사한다. |
| 실수→정수 변환 | 범위 이탈, 소수부, NaN(Not a Number), 무한대를 명시적으로 처리한다. |
| 실수 폭 변경 | 유한 값의 정밀도 손실과 특수값 처리 규칙을 정의한다. 음의 0 및 NaN 비트 표현 보존이 필요한 기능은 수치적 동일성과 구분한다. |

0 나누기, 부호 있는 정수의 `MIN / -1`, `MIN % -1`, `MIN.abs()` 및 `-MIN`을 경계 오류 검사에 포함한다.

초기 API는 오류를 반환하는 명시적 메서드를 우선한다. 결과를 오류로 반환할 수 없는 대입 연산자로 실패를 숨기지 않는다.

시프트 횟수 검사와 값의 정보 손실 검사를 구분한다. 표준 `checked_shl`은 횟수가 유효해도 밀려 나가는 비트 때문에 값이 달라질 수 있다. 예를 들어 `255_u8.checked_shl(1)`은 `Some(254)`다.

무손실 시프트는 유효한 횟수와 함께 왼쪽 이동의 표현 가능성, 오른쪽 이동의 정보 손실을 검사한다. 부호 있는 수의 규칙도 별도로 명시한다. 일반적인 비트 절단 시프트가 필요한 경우 손실을 허용한다는 의미가 드러나는 별도 API로 제공한다.

### 3.7 시스템 런타임·동기화·시간·입출력 (`jzap::thread`, `jzap::sync`, `jzap::time`, `jzap::io`, `jzap::path`)

| 항목 | 요구사항 |
| --- | --- |
| `thread::try_spawn` | 운영체제 생성 실패, 이름 검증, 내부 핸들·클로저 저장·공유 상태의 할당을 함께 검토한다. 내부 할당이 실패 불가능한 표준 API에 단순 위임하여 보장을 선언하지 않는다. |
| `Mutex<T>` / `RwLock<T>` | 오염 상태와 지원 백엔드의 동기화 오류를 명시적으로 반환한다. 복구 여부는 호출자가 선택한다. |
| `Instant` / `Duration` | 시간 차이, 역순 입력, 누적·가감산 오버플로우를 검사한다. 시간 원천과 대상 플랫폼의 의미를 문서화한다. |
| `try_print` / `try_eprint` | 파이프 단절, 쓰기 실패, 내부 버퍼 확보와 포맷팅 실패를 처리한다. 출력된 부분을 취소할 수 없다는 계약을 명시한다. |
| `PathBuf` / `OsString` | 경로·OS 문자열 저장과 확장을 실패 가능하게 제공한다. 유효한 비 UTF-8 OS 표현을 보존하고, UTF-8 변환 오류는 별도로 반환한다. |

표준 `Builder::spawn`은 운영체제 스레드 생성 실패를 이미 반환하지만, 구현 내부에 실패 불가능한 할당이 있을 수 있다. 대상별 구현 경로가 검증되기 전에는 해당 플랫폼의 지원 완료로 표시하지 않는다.

표준 Mutex/RwLock도 이미 오염 상태를 반환한다. 새 타입은 추가로 제공하는 계약을 명확히 해야 한다. 재진입, 잠금 순서, 대기 기한과 교착 방지는 자원 할당 실패 처리와 별도 요구사항으로 관리한다. 알 수 없는 교착상태를 자동으로 오류로 바꾸는 것으로 기술하지 않는다.

현재 Rust의 역순 `Instant - Instant`는 0으로 포화될 수 있다. 새 API는 이러한 입력 순서 문제를 명시적으로 검출한다. 검출된 역순 입력이 곧바로 운영체제 시계의 실제 역전을 입증하는 것은 아니다.

자원 종료나 flush에서 오류 보고가 필요하면 명시적 종료 메서드를 제공한다. `Drop`에서 실패를 보고하기 위해 패닉하거나 새로운 진단 메모리를 할당하지 않는다. 사용자 소멸자의 행동은 2.3절의 전제조건을 따른다.

### 3.8 정적 차단 및 정책 강제 (`jzap-policy`)

| 대상 | 정책 |
| --- | --- |
| 표준 소유 타입 | 엄격한 적용 코드에서 표준 Box, Arc/Rc, Vec, String, HashMap, BTreeMap, VecDeque, BinaryHeap 등의 직접 사용을 검사한다. |
| 중단·임시 구현 매크로 | 제품 런타임의 `panic!`, `todo!`, `unimplemented!`, `unreachable!` 및 패닉을 발생시키는 assertion 사용을 검사한다. |
| 암묵적 할당·출력 | `vec!`, `format!`, 표준 출력·디버그 매크로와 `ToOwned`, `ToString`, `FromIterator`, `Extend` 등의 실행 경로를 검사한다. |
| 직접 실패 강제 | `unwrap`, `expect`, 직접 인덱싱, 표준 `thread::spawn` 등의 사용을 검사한다. |
| 수치 변환 | `cast_possible_truncation`, `cast_sign_loss`, `cast_possible_wrap`, `cast_precision_loss` 등과 API 계약을 함께 검토한다. 무손실 `as` 변환은 `From` 등으로 정리할 수 있다. |
| 검증 코드 | 테스트·벤치마크·형식검증 하네스의 assertion과 의도적인 실패 주입은 제품 런타임과 분리하여 허용한다. |

타입 수준의 메서드 부재는 해당 위험 API의 직접 호출을 컴파일 오류로 차단한다. Clippy 정책은 호출자 코드의 실수를 추가로 검출한다. 두 기능을 전체 프로그램에 대한 동일한 수준의 증명으로 취급하지 않는다.

원시 뷰, 표준 타입 변환, FFI(외부 함수 인터페이스), 매크로 생성 코드와 외부 의존성은 상호운용 경계 목록에 기록한다. 공개된 가변 소유 컨테이너나 할당을 수행하는 `Clone`이 가능한 소유 반복자로 정책을 우회하지 못하게 한다.

정책의 예외는 이유·위치·유효한 대상 구성을 기록한다. 단순히 빌드를 통과시키기 위해 워크스페이스 전체의 검사를 비활성화하지 않는다. 필수 검사는 지속적 통합(CI) 구성에 연결하되, 비공개 저장소에서는 별도 지시 전까지 자동 실행과 임의의 수동 실행을 하지 않는다.

## 4. 공통 API 및 실패 후 상태 계약

### 4.1 메서드별 필수 명세

각 공개 연산에는 다음 정보를 둔다.

| 항목 | 명세 내용 |
| --- | --- |
| 오류 조건 | 범위, 용량, 예산, 할당, 사용자 콜백의 반환 오류 등 |
| 입력 소유권 | 거부된 소유 입력의 반환 여부와 소비된 반복자 원소 범위 |
| 기존 상태 | 내용, 길이, 순서, 키·값과 인덱스 불변식의 보존 여부 |
| 용량 | 성공한 선행 예약 이후 용량이 남을 수 있는지 |
| 부분 진행 | 전부 취소, 접두 부분 유지, 명시적 진행량 반환 중 어느 계약인지 |
| 예산 | 예약·성공·취소·해제 시 청구와 반납 시점 |
| 콜백 | 호출 횟수·순서와 부작용 및 반환 오류에 대한 전제조건 |
| 복잡도 | 정상 경로, 성장 경로 및 실패 정리 경로의 시간·공간 비용 |

단건 소유 입력의 거부에는 `Rejected<T>`와 같은 비할당 반환형을 사용할 수 있다. 전체 오류 계층과 정확한 타입 이름은 기초 API 설계에서 확정한다.

### 4.2 기본 동작

- 단건 추가·삽입은 입력을 반영하기 전 필요한 검사를 수행한다. 거부 시 기존 데이터를 유지하고 소유 입력을 반환한다.
- 두 컨테이너 사이의 이동은 목적지 확보가 실패하면 양쪽 입력을 보존한다.
- 새 객체 생성 중 실패하면 완성되지 않은 결과를 외부에 노출하지 않고 초기화된 부분을 정확히 한 번 정리한다.
- 기존 객체에 깊은 복사나 문자열 포맷팅을 추가하다 반환 오류가 발생하면, 기본 트랜잭션 API는 기존 내용을 복원한다. 용량 보존 여부는 별도 명시한다.
- 부분 성공 API는 이름과 반환값으로 진행량을 드러낸다. 반복자 진행, 콜백의 외부 부작용과 이미 수행한 입출력을 자동으로 되돌린다고 약속하지 않는다.
- 라이브러리 내부에서 자원을 무제한 재요청하거나 데이터를 임의로 제거하지 않는다.

### 4.3 트레이트와 상호운용

할당하거나 실패할 수 있는 소유 타입에 일반 `Clone`, `Index`, 암묵적 할당 `From`·`Into`·`FromIterator`·`Extend`를 제공하지 않는다. 실제로 실패하지 않는 스칼라 복사·무손실 변환·빈 값 생성까지 일괄 금지하지는 않는다.

소유 타입의 원시 표현과 가변 백엔드 컨테이너는 비공개로 유지한다. 엄격한 소유 타입은 `Deref`를 통해 표준 Vec·String이나 원시 슬라이스·str의 인덱싱을 암묵적으로 다시 노출하지 않는다. 원시 뷰가 필요한 경우 명시적 상호운용 메서드로 제공하고 정책 검사 대상에 포함한다. `Box<T>`의 역참조처럼 값 `T`를 노출하는 API는 `T` 자체의 메서드까지 보장하는 것으로 해석하지 않는다. 표준 타입과의 변환에는 복사 여부, 예산 소유권, 보장 경계 변경을 명시한다.

### 4.4 초기화와 정리 계약

`try_new(value)`는 이미 만들어진 값을 받는다. 공간 부족 시 그 값과 오류를 함께 반환한다. 값 생성 자체를 뒤로 미뤄야 하는 경우에는 저장소 확보 이후 초기화 함수를 호출하는 API를 사용한다. 큰 값을 스택에 먼저 완성하지 않아야 하는 경우에는 별도의 제자리 초기화 API를 사용한다.

`TryInit`의 안전한 호출 경로는 초기화 완료를 단순한 `Ok(())` 선언에 맡기지 않는다. `&mut MaybeUninit<T>`를 받은 사용자가 아무것도 쓰지 않고 `Ok(())`를 반환해도 완성된 `T`가 만들어지는 API는 허용하지 않는다. 초기화 기록을 관리하는 작성 인터페이스 또는 구현자에게 초기화 의무를 부과하는 명시적 unsafe 계약으로 완료 상태를 보장한다.

- 초기화 전에는 완성된 `T`의 참조를 만들지 않는다. 저장소 주소와 초기화된 필드·원소의 접근을 구분한다.
- 반환 오류가 발생하면 초기화된 부분만 정확히 한 번 소멸시키고 저장소와 예약을 회수한다.
- 초기화 함수의 고유 오류는 새 문자열이나 Box로 감싸지 않고 보존할 수 있어야 한다.
- 제자리 초기화와 고정된 주소를 요구하는 초기화는 구분한다. pin 초기화를 제공할 때는 초기화 이후 이동 금지 조건까지 별도로 검증한다.
- 크기 0 타입, 큰 정렬, 부분 초기화, 오류 후 재시도와 실제 소멸 경로를 검사한다. 사용자 소멸자에 대한 전제조건은 2.3절을 따른다.

### 4.5 호출자 제공 버퍼와 재시도

외부 버퍼를 받는 API는 출력 저장소와 내부 작업 저장소를 구분한다. 출력만 외부에서 받고 작업 버퍼를 내부에서 할당한다면 그 API를 무할당 API로 표시하지 않는다. 알고리즘 연동 계층에서 압축·디코딩 문맥이나 외부 라이브러리를 사용할 경우에도 동일한 기준을 적용한다.

무확장 API에는 다음 계약을 적용한다.

1. 제공된 용량 안에서만 동작하며 부족하면 오류를 반환한다. 자동 확장이나 숨겨진 대체 할당을 하지 않는다.
2. 사전 계산 가능한 필요량과 정렬 조건을 조회하거나 오류에서 확인할 수 있게 한다. 필요량 계산 자체의 오버플로우와 한도 초과도 오류로 처리한다.
3. 실제로 필요한 저장소가 입력 처리 중에만 결정된다면, 오류 시 처리한 입력·출력 범위와 재시도 지점을 명시한다. 알 수 없는 정확한 필요량을 임의의 숫자로 표현하지 않는다.
4. 호출자는 오류 종류에 따라 더 큰 버퍼를 준비하여 다시 호출하거나 작은 범위의 스트리밍 API를 선택할 수 있다. 할당 거부와 정책상 한도 초과를 같은 재시도 조건으로 취급하지 않는다.
5. 반환 오류 후 처음부터 재시도하는 API와 진행 위치에서 이어가는 API를 구분한다. 콜백으로 이미 전달한 데이터의 중복 처리와 늦은 검증 실패에 따른 취소 책임을 명시한다.

초기 구현에서는 바이트 scratch와 크기를 알 수 있는 안전한 작성 연산부터 제공한다. 일반 `T`에 대한 부분 초기화 scratch는 4.4절의 정리 계약을 갖춘 뒤 확장한다. 압축 포맷과 코덱 자체의 구현은 이 라이브러리의 기본 개발 범위에 추가하지 않는다.

## 5. 메모리 예산 모델

### 5.1 할당과 계측의 분리

기본 설계는 기존 전역 할당자를 그대로 사용한다. `jzap` 소유 타입과 내부 저장소가 요청하는 메모리를 논리적으로 계측한다. 고정 아레나나 별도 하드웨어 할당자는 기본 구현의 필수 조건이 아니다.

`MemoryBudget`의 기본 단위는 관리 경로가 요청한 할당 레이아웃의 바이트다. 정렬 요구는 할당 요청에 반영하되, 할당자가 내부적으로 추가한 메타데이터·크기 반올림·단편화와 프로세스 상주 메모리까지 정확히 계측한다고 주장하지 않는다.

예산에 포함되는 메모리는 요청된 버퍼와 제어 블록이다. 아직 실현되지 않은 예약과 실현된 점유를 구분하고 다음 불변식을 유지한다.

```text
실현된 점유량 + 아직 실현되지 않은 예약량 <= 예산 상한
```

성공 시 예약을 점유로 전환하고, 실패 시 예약을 취소한다. 실제 해제가 완료되면 점유를 반납한다. 계수의 덧셈·뺄셈 자체도 오버플로우·중복 반납 없이 동작해야 한다.

### 5.2 재할당과 순간 사용량

기존 버퍼가 살아 있는 동안 새 버퍼를 확보할 수 있으므로, 강한 요청량 상한을 제공하는 기본 정책은 기존 점유를 유지한 채 새 요청 전체를 예약한다.

MiB는 1,048,576바이트 단위다. 예를 들어 8MiB 버퍼를 12MiB로 교체할 때 기존·신규 저장소가 겹칠 수 있는 구간은 20MiB로 취급한다. 할당자가 제자리 확장할 수도 있다는 추측만으로 증가분 4MiB만 청구하지 않는다. 이 보수적 정책은 실제 제자리 확장이 가능했던 요청도 거부할 수 있으며, 이는 명시된 정책의 결과다.

중첩된 `Vec<String>`의 외부 버퍼와 각 문자열 할당은 각각 관리 경로를 통해 같은 예산에 포함할 수 있어야 한다. 외부 사용자 타입이 별도로 만든 메모리는 자동으로 계측되지 않는다.

### 5.3 공유·수명·동시성

- 공유 핸들을 복제할 때 동일 할당을 중복 청구하지 않는다.
- 예약 객체의 생성·반납은 그 자체로 힙 할당을 요구하지 않도록 설계한다.
- 예산 객체와 예약 토큰의 수명 관계를 타입으로 표현하고, 예산이 먼저 소멸하여 해제 시 접근이 무효화되지 않도록 한다.
- 예산 핸들 자체에 공유 포인터가 필요하면 최초 구성 실패와 카운트 상한도 처리한다.
- 동시 예약은 하나의 원자적 승인 절차 또는 검증된 잠금 절차로 상한을 지킨다.
- 내부 예산 잠금을 보유한 채 임의 사용자 콜백을 실행하여 재진입·잠금 순서 문제가 생기지 않게 한다.
- 소유 저장소를 표준 타입으로 넘기거나 예산 사이에 이동할 때, 저장소가 살아 있는 동안 청구만 먼저 사라지지 않게 한다. 양도 시점과 책임 이전을 표현하지 못하는 변환은 제공하지 않는다.
- 예산 구성 자체가 숨겨진 실패 불가능한 공유 할당에 의존하지 않게 한다. 호출자가 소유하는 무할당 예산 구성과 공유 핸들을 소유하는 구성을 구분한다.

### 5.4 제한 기능의 구분

| 기능 | 제한하는 것 |
| --- | --- |
| `MemoryBudget` | 지정된 관리 경로 전체의 요청 바이트 점유·예약 |
| `BoundedVec` / `BoundedString` | 개별 객체의 요소 수 또는 바이트 길이 |
| `ScratchBuf` | 해당 저장소의 실행 중 추가 할당·재할당 |
| 할당 실패 주입 | 낮은 한도와 특정 실패 순번을 이용한 개발·검증 동작 |

상한만 있는 컨테이너가 이미 모든 저장소를 확보했다는 뜻은 아니다. 사전 확보와 상한 설정은 API에서 구별한다. 예산 없는 동작이 필요하면 소비자가 명시적으로 선택하며, 설정되지 않은 예산을 조용히 무제한으로 대체하지 않는다.

### 5.5 작업량과 종료 조건

메모리 한도는 작업량 한도가 아니다. 크기 0 타입의 매우 긴 컬렉션, 충돌이 많은 해시 입력, 끝나지 않는 반복자 또는 계속 중단되는 입출력은 작은 메모리로도 긴 실행을 유발할 수 있다.

유한 입력을 순회하는 내부 루프는 검증된 실제 길이·원소 수에 의해 제한되거나 남은 작업량이 감소해야 한다. 신뢰할 수 없는 메타데이터나 반복자의 `size_hint`만을 근거로 과도한 선할당·반복을 시작하지 않는다. 큰 정상 입력을 일괄 차단하는 임의의 기본 상한은 추가하지 않는다.

필요한 API에는 요소 수, 단계 수, 재시도 횟수 또는 취소 확인 같은 작업량 정책을 별도로 제공한다. 작업 한도 소진 시에는 4절에 따른 상태와 진행량을 반환한다. 단일 사용자 콜백의 무한 실행, 운영체제 호출의 영구 대기와 교착을 작업 카운터로 강제 중단할 수 있다고 약속하지 않는다. 원자 연산의 재시도 루프는 입력 순회와 구분하여 동시성 진행 조건을 명세하며, 검증 없이 개별 호출의 대기 시간 상한이나 기아 방지를 주장하지 않는다.

## 6. 빌드 및 플랫폼 구성

기본 구현은 `#![no_std]`를 우선한다. 힙이 필요 없는 기능은 `core`만으로, 소유 저장소는 `alloc`으로 제공하고, 운영체제 연동이 필요한 기능만 명시적 `std` 기능으로 분리한다. 기본 기능 구성은 `std`를 활성화하지 않는다. `no_std + alloc`도 할당 실패 가능성을 없애지는 않으며 동일한 실패 반환 계약을 적용한다. 각 지원 구성은 독립적으로 빌드·검증한다.

제품 런타임의 직접·전이 의존성을 최소화한다. 의존성마다 필요한 기능, 대체 가능성, 활성 기능, 코드 크기·메모리·검증 비용을 기록한다. 기존 코드를 차용한다는 이유로 해당 저장소의 의존성 전체를 가져오지 않는다. derive·검증·벤치 도구는 선택적 빌드 도구 또는 개발 전용 의존성으로 분리한다. 검증된 구현을 무리하게 다시 작성하여 의존성 개수만 줄이지는 않으며, 추가 의존성은 필요성을 입증한 경우에 한해 채택한다.

| 구성 | 내용 |
| --- | --- |
| `core` 기반 | 오류 표현, 검사 산술, 검사된 뷰, 힙을 요구하지 않는 예산·상태 구성 요소 |
| `alloc` 기반 | Vec, String, Box, 컬렉션 및 할당을 사용하는 포인터 |
| `std` 기반 | 운영체제 스레드, 동기화 백엔드, 시간, 입출력, 경로 및 OS 문자열 |
| derive 패키지 | 별도 `jzap-derive` proc-macro 패키지. 생성한 런타임 코드의 계약과 빌드 도구 자체를 구분 |
| 정책 패키지 | `jzap-policy`의 린트 설정, 검사 도구와 적용 예제 |

최소 지원 Rust 버전과 기능별 대상 목록은 첫 배포 전에 고정한다. 특정 플랫폼의 검증을 다른 플랫폼의 검증으로 대체하지 않는다. Arc에 필요한 원자 연산이 없는 대상에서는 검증된 별도 백엔드 없이 해당 기능을 활성화하지 않는다.

기능 선택에 따라 실패 가능한 API의 내부 구현이 오류를 숨기는 표준 연산으로 조용히 바뀌어서는 안 된다. 지원하는 각 기능 조합과 대상에서 내부 할당 경로를 확인한다.

`unsafe`는 저장소·초기화·참조 카운트 등 필요한 내부 구현에 한정한다. 각 사용에는 초기화, 소유권, 정렬, 범위 및 수명 조건을 기록한다. 제품 런타임과 테스트의 거부 가능한 할당자 구현을 분리한다.

## 7. 검증 체계와 완료 기준

### 7.1 공통 검증

도구는 검증할 속성에 맞춰 선택한다. 모든 API에 같은 도구를 형식적으로 실행하는 것을 완료 기준으로 삼지 않는다. 중단되거나 탐색 한도를 충족하지 못한 증명은 통과로 기록하지 않는다.

지원 상태와 검증 근거는 별도로 기록한다. API별로 기능·대상·소스 커밋, 구체화한 타입, 입력 범위, 할당자·콜백 모델, 실행한 검사 플래그와 통과·실패·미지원 결과를 연결한다. 기능 테스트 통과를 모든 타입과 모든 길이에 대한 형식증명으로 확대하지 않는다.

Kani의 컴파일러 오류, 지원하지 않는 union·enum·간접 호출, 메모리 초기화·값 유효성 검사 실패는 완료된 증명으로 계산하지 않는다. 추상 모델을 쓸 때는 실제 구현과의 연결을 제시한다. 검사를 꺼서 얻은 결과와 같은 검사를 켠 결과를 구분한다. Miri·Loom의 통과 역시 실행한 입력과 탐색한 상태 범위에 맞게 해석한다.

로컬 경로나 저장소에 포함한 의존성은 lockfile 감사에서 원본 패키지 자체의 권고가 누락될 수 있다. 해당 원본의 버전·보안 권고·패치 상태를 별도로 확인하고, 원본 버전 번호만으로 유지 패치의 적용 여부를 판단하지 않는다.

### 7.2 결함 검출력 확인

대표적인 불변식에는 별도 복사본에서 의도적으로 길이 증가, 예산 반납, 참조 카운트 전이 등을 잘못 변경하는 대조 검사를 둔다. 하네스가 실제 결함을 검출하는지 확인하며, 빌드 실패를 증명 성공으로 계산하지 않는다.

테스트에서만 작은 카운트·용량 한도를 적용할 때는 실제 구현의 전이 로직을 재사용한다. 제품과 분리된 장난감 모델만 검증하고 제품의 보장으로 표시하지 않는다.

### 7.3 API 지원 완료 조건

1. 공개 API의 정상·실패·소유권·예산 계약이 문서화되어 있다.
2. 내부 호출과 의존성에서 해당 계약을 우회하는 실패 불가능한 경로가 검토되었다.
3. 의미 비교, 실패 주입, 오류 후 재사용 및 필요한 메모리·동시성 검사가 통과했다.
4. 형식검증을 보장 근거로 사용하는 속성은 구현 연결과 한도를 포함하여 완료되었다.
5. 8절의 성능 기준과 대상 사용 경로가 기록되었다.
6. 지원 대상, 기능 조합, 도구 체인과 소스 커밋에 증거가 연결되어 있다.

## 8. 성능 평가 기준

### 8.1 공정한 비교 조건

일차 비교 대상은 채택한 Rust 버전의 원본 std 대응 타입·연산이다. 목표는 동일한 성공 작업에서 기능적 동등성을 유지하면서 처리 속도와 실제 메모리 사용량이 원본 std와 유사한 것이다. 실패 반환 방식, 명시적으로 선택한 예산·상한 정책과 의도적으로 제거한 위험 API는 차이로 기록한다. 그 외 값, 순서, 키 갱신, 소유권 효과와 관찰 가능한 동작은 대응 계약을 유지한다. std가 순서를 보장하지 않는 항목은 특정 실행의 우연한 순서까지 동일하게 요구하지 않는다. 내부 레이아웃·ABI의 동일성을 뜻하지 않는다.

원본 std의 기본 설정을 사용한 비교를 필수로 수행한다. 해셔·성장 정책·인라이닝 등을 맞춘 비교는 차이의 원인을 설명하는 보조 실험이며 원본 std 대비 결과를 대체하지 않는다. 서로 다른 알고리즘을 선택한 경우에도 실제 소비 작업을 같게 맞추고 성능·메모리 차이를 공개한다.

원인 분석용 대조에서는 알고리즘, 해셔, 입력, 초기 용량, 성장 정책, 최적화 수준, 인라이닝 및 링크 설정을 맞춘다. 원본 std 비교와 이 대조 결과를 별도로 표시한다.

동일 구현을 양쪽에 사용하는 대조 측정, 실행 순서 교대, 독립 프로세스 반복과 원본 측정값 보관을 포함한다. 시간 측정 중 컴파일·형식검증 등 다른 부하를 피한다. 관찰된 큰 차이는 생성 코드와 실험 조건을 조사한다.

### 8.2 측정 항목

- 여유 용량 내 정상 연산, 신규 성장, 기존 값 갱신, 충돌·삭제 후 동작.
- 단일 할당, 재할당, Copy 일괄 처리, 깊은 복사와 포맷팅.
- 실패 반환, 부분 결과 정리, 예산 거부와 반복 복구.
- 처리 시간과 지연 분포, CPU 시간, 최고 상주 메모리(RSS), 할당 횟수·요청량·순간 요청량, 코드 크기.
- 외부 저장소나 이식 대상의 작업 경로에서 사용하는 임시 파일의 논리·실제 할당 공간과 입출력량.
- 대용량·중첩·복합 입력, 단일 writer 및 다중 reader의 동일 작업량 비교.
- 예산 계측을 켠 구성과 끈 구성, 공유 예산·참조 카운트의 경쟁 비용을 구분한 비교.
- 실제 지원 대상 하드웨어에서의 동일 작업량 측정.

각 구현 단위의 수정 전 기준선을 확보하고 수정 후 회귀 검사와 전후 벤치를 수행한다. 성능 비교 중 CPU·메모리·임시 저장 공간 한도를 늘려 결과를 맞추지 않는다. 실패·회귀·시간 초과와 초기 관측을 원본 기록에 보존한다. 추가 측정의 조건과 통합 방식을 사전에 정하고 유리한 반복만 골라 보고하지 않는다.

### 8.3 적용 판정

속도와 메모리의 유사성은 각각 독립적인 필수 수용 기준이다. 요청 바이트나 논리적 예산만으로 실제 사용 메모리가 유사하다고 판정하지 않는다. 동일 할당자·대상·작업량에서 컨테이너 및 원소당 오버헤드, 유지 용량, 순간 피크, 가능한 경우 할당자의 실점유량과 프로세스 RSS를 함께 측정한다. 고정비, 할당자 메타데이터·단편화, 공유 제어 블록과 예산 관리 비용을 포함하며 RSS의 측정 한계도 기록한다. 예산 미사용·사용 구성을 모두 비교하여 비용을 숨기지 않는다.

구현 전에 작업별 속도·메모리 허용 편차와 측정 불확실성 처리 방법을 수치로 정한다. 측정 후 기준을 완화하여 유사하다고 판정하지 않는다. 기능적 동등성, 속도, 메모리 중 하나라도 기준을 충족하지 못하면 동등한 대체 구현으로 승인하지 않으며, 원인과 차이를 기록하고 개선하거나 별도의 선택 기능으로 분류한다.

핫패스는 해당 사용 경로의 허용 비용을 먼저 정하고, 통계적으로 구별되는 회귀와 불확실한 결과를 별도로 표시한다. 측정 해상도 안에서 차이가 작다는 사실을 오버헤드 0으로 표현하지 않는다.

작은 비용을 허용할 수 있는 낮은 빈도의 경로는 허용 이유와 절대 비용을 기록한다. 성능 기준을 충족하지 못한 기능은 자동 이식 대상에서 제외하고 개선하거나 소비자가 명시적으로 선택하게 한다.

기준을 맞춘 뒤 비용을 검토한다. 오류 반환을 위해 다른 자료구조나 요소별 복사를 도입했다면 동일한 물리적 동작이라고 기술하지 않는다.

현재 Varlit 범위 스트리밍은 외부 출력 scratch를 사용하지만 zstd 문맥과 일부 내부 저장소는 별도로 할당한다. 이를 압축·디코딩 작업 공간까지 전부 외부에서 받는 무할당 API의 완성품으로 차용하지 않는다.

기준 커밋에는 기본·전체 기능 구성 각각 50개 일반 Kani 하네스의 통과 기록이 있다. 이 가운데 소유권 하네스는 15개이며, 실제 helper를 사용하되 바이트 벡터 최대 4개 원소, 중첩 Box 복제 최대 3개 원소, 3바이트 COW와 단일 스레드 참조 카운트 등 명시된 범위를 사용한다. 전체 타입·길이·동시성에 대한 메모리 부족(OOM) 불가능성 증명은 아니다.

추가 검사에서는 Kani 0.68.0의 컴파일러 오류를 고친 upstream 커밋 `947fcec757d9b6a2d07283a0952aaa088e1d8df1`을 확인했다. 전체 소유권의 추가 미초기화·값 유효성 검사는 union·enum 및 포인터 처리의 미지원 경로 등으로 여전히 막혀 있다. 후속 커밋의 일반 검사는 기본·전체 기능 각각 52/52가 통과했다. 추가 플래그를 적용한 제한된 검사는 값 유효성 2개와 할당 거부 시 초기화 검사 1개가 통과했지만, 전체 소유권 추가 검사는 0/4로 미완료다. 자체 타입으로 옮긴다는 사실만으로 이 도구 한계가 해소되었다고 취급하지 않는다. 이식 후의 구체화 타입과 실제 초기화·소멸 경로를 다시 검증한다.

참고 코드는 알고리즘, 실패 계약, 검증 하네스를 단위로 비교하여 통합한다. 동일 기능의 두 구현을 무조건 함께 보관하지 않으며, 선택한 원본·차이·라이선스와 증거를 추적한다. 새 예산·타입·오류 계약을 적용한 결과는 별도 검증한다.

## 10. 구현 순서 및 산출물

| 순서 | 구현 범위 | 다음 단계로 넘길 산출물 |
| --- | --- | --- |
| 기초 규격 | 오류, 실패 후 상태, 예산 모델, TryClone/TryInit 서명, 빌드 구성, 정책 범위 | API 계약표, 할당 경로 목록, 검증·벤치마크 실행 기반 |
| 기본 소유 타입 | Vec, String, Box, 검사된 뷰, Checked 수치와 변환, bounded 타입 및 ScratchBuf | 재사용 가능한 단위 연산, 실패 주입·메모리 검증 및 성능 결과 |
| 확장 컬렉션 | HashMap/Set/Entry, VecDeque, BinaryHeap, SortedMap/Set | 탐색·성장·부분 실패의 의미 계약과 데이터별 성능 결과 |
| 공유 소유권 | Rc/Weak, Arc/Weak, 동시 예산 통합 | 카운트 포화와 마지막 해제를 포함한 동시성 검증 |
| 시스템 런타임 | 스레드, 잠금, 시간, 입출력, OS 문자열·경로 | 지원 플랫폼별 내부 할당·오류 경로 검증 |
| 소비 라이브러리 이식 | 소유 타입, TryClone, 오류 전파, 상태 업데이트 경계 | 실제 API 의미 비교, 자원 부족 시 상태 보존, 대상 제품 성능 결과 |

첫 납품 범위는 기초 규격과 기본 소유 타입이다. 바이트 중심의 외부 scratch와 Vec·String·Sized Box의 정상·실패 계약을 먼저 확보하고, 일반 원소의 부분 초기화, Box 슬라이스와 추가 편집 연산으로 넓힌다. 공유 소유권은 카운트 상한과 Weak 수명 규칙을 완성하기 전까지 표준 clone 위임으로 채우지 않는다.

기초 단계에서는 다음 설계를 확정한 후 해당 단위 구현에 들어간다.

- 오류 계층과 소유 입력 반환형, 대상 예산을 전달하는 복제·초기화 서명.
- 예산 객체와 예약 토큰의 수명·공유 방식 및 전역 할당자 경계.
- 기본 검사 뷰와 명시적 상호운용 API, derive의 제네릭·별칭·crate 경로 처리.
- 지원 Rust 버전, 초기 대상과 기능 구성, 각 검증 도구의 실제 적용 범위.
- 대표 작업량, 자원 한도와 성능 수용 기준.

단계별로 필요한 기초 검사를 먼저 갖추고 구현과 검증을 함께 진행한다. 전체 목표를 유지하되 완료되지 않은 모듈을 우회 구현으로 채워 지원 완료로 표시하지 않는다.

소비 라이브러리 이식은 공통 단위가 준비된 후 타입과 메서드를 모듈 단위로 전환한다. 컴파일러로 누락을 찾고, `Result`를 자원 업데이트 경계까지 전파한다. 개별 호출부 앞에 사전 검사를 덧붙이는 작업으로 공통 계층 구현을 대체하지 않는다.

## 11. 범위 목록 및 유지보수

공개 API와 내부 의존 경로의 목록을 유지하며 각 항목을 지원, 검증 중, 구현 예정, 명시적 범위 밖으로 표시한다. 구현 여부만으로 보장 수준을 판단하지 않는다.

정렬의 임시 저장소, `ToOwned`·`Cow`·수집 어댑터, 사용자 콜백, 외부 매크로의 숨은 할당도 경로 목록에서 검토한다. `RefCell`, `Once`·`Lazy` 계열과 채널 등 원안의 구체적 구현 목록에 없던 표준 기능은 범위 결정을 기록하고, 지원하지 않는 동안 자동으로 대체되었다고 간주하지 않는다.

업스트림을 따라갈 때는 원본 버전, 유지 패치, 의미 변경, 의존성 기능 및 검증 결과를 함께 갱신한다. 원본 소스 전체를 보관한 줄 수와 실제 수정량은 구분한다. 각 소비 프로젝트에서 같은 패치를 다시 유지하지 않도록 공통 구현을 한곳에 두고 검토된 버전이나 커밋을 참조한다.

기존 소비 API와의 타입·반환형 호환성 변경은 명시한다. 검증 결과는 도구 체인·대상·기능·소스에 연결하여 보관한다. 별도 제품의 규제 적합성이나 인증은 라이브러리 자체의 테스트 통과와 구분한다.
